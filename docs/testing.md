# Проверка проекта

Режимы разделяют проверку платы, внешних устройств и эмуляции. Измерения логической скорости игры и скорости SPI следует оценивать отдельно.

## Плата без внешних устройств

```bash
bash scripts/build.sh board-check
bash scripts/flash.sh board-check "$port"
python scripts/capture_serial.py --port "$port" --output .private/board-check.log --seconds 20 --reset
```

Ожидаются:

- `PIN_AUDIT PASS`: уникальные назначения управляющих GPIO, USB-FS pad освобождён.
- `CODEC_I2C PASS`: ES8311 отвечает по адресу 0x18.
- `PSRAM_TEST PASS`: размер 32 MiB, четырёхпроходная проверка доступной области.
- `BOARD_CHECK PASS` и периодические сообщения `ALIVE`.

## Дисплей, кнопки, звук и microSD

Подключите устройства по [таблице GPIO](hardware-plan.md), при снятом питании.

```bash
bash scripts/build.sh peripheral-test
bash scripts/flash.sh peripheral-test "$port"
python scripts/capture_serial.py --port "$port" --output .private/peripherals.log --seconds 30 --reset
```

Проверьте:

1. Восемь цветовых полос в альбомной ориентации. Угловые маркеры: красный сверху слева, зелёный сверху справа, синий снизу слева, белый снизу справа.
2. Нажатие и отпускание каждой кнопки, затем сочетания направлений с A/B/C. Изменения отражаются в журнале.
3. Короткий тон 440 Hz через штатный динамик.
4. `ROM_LOADED` с ожидаемым размером и SHA-256 файла с карты.
5. `PINMUX_CHECK PASS` после инициализации драйверов и работы SDMMC.

Успешный SPI DMA подтверждает завершение передачи ESP32-P4. Видимость, ориентация и цвета проверяются на самой панели; слышимость проверяется через подключённый динамик.

## Игра

Соберите и запишите `play`, как описано в [инструкции macOS](build-macos.md). Проверьте Start, направления, A/B/C, игровой звук и переходы между сценами.

В журнале:

- `EMU_STATS fps_x100`: логические кадры/с, умноженные на 100.
- `DISPLAY_STATS presented`: число переданных изображений; `last_transfer_us`: время последней передачи.
- `AUDIO_STATS pcm_starvations` и `write_errors`: нехватка PCM и ошибки записи.
- `internal_free` и `stack_min_bytes`: доступная внутренняя память и запас стека.

Счётчик `late` накопительный: он отмечает отдельные кадры, вычисление которых завершилось позже срока более чем на 2 мс. Кратковременные задержки при растеризации или выводе UART оцениваются вместе с общей скоростью и непрерывностью PCM.

Для NTSC целевой темп ядра составляет около 59,9 кадра/с. В измеренном запуске ESP32-P4 v1.3 с CPU 360 MHz, PSRAM 200 MHz, XIP и L2 cache 256 KiB сценарий 7200 кадров занял около 120,25 с с завершением аудио. При SPI 20 MHz передача 320×224 занимала около 60 мс. Более быстрый темп SPI проверяется отдельно для конкретного модуля и проводки.

## Нативные проверки без платы

Для утилит нужен компилятор C с AddressSanitizer/UndefinedBehaviorSanitizer, например Xcode Command Line Tools:

```bash
bash scripts/check.sh
```

Проверяются дребезг, сочетания кнопок, переполнение временного счётчика, пересчёт звука NTSC/PAL, непрерывность фазы при разбиении на блоки и ограничения выходных буферов.

Полное ядро можно запустить под AddressSanitizer со своим ROM:

```bash
python3 scripts/host_check.py "/path/to/game.gen" --frames 7200
python3 scripts/host_check.py "/path/to/game.gen" --frames 7200 --render-every 4 --output .private/host-skip
```

Вывод и снимки остаются локально в `.private/`. Сценарий подаёт Start на кадре 1900. При сравнении полной отрисовки и пропуска пикселей оцениваются строки `FRAME`, `AUDIO_FRAME` и файл PCM. Это проверка ядра; она не заменяет физические проверки GPIO, TFT, карты и динамика.

## Локальный диагностический ROM-тест

Для прямого сравнения с нативным запуском:

```bash
bash scripts/build.sh rom-test "/path/to/game.gen"
bash scripts/flash.sh rom-test "$port"
python scripts/capture_serial.py --port "$port" --output .private/rom-test.log --seconds 140 --reset
```

Этот режим встраивает выбранный локальный ROM в диагностический образ. Сборка хранится в `.private/build-rom-test/`. После проверки верните `play` для обычной загрузки с microSD. Диагностические образы, захваты и ROM-файлы в репозиторий не включаются.

В обычном режиме `play` автоматического нажатия Start нет. На карте должен находиться собственный ROM; в прошивку `play` он не встраивается.
